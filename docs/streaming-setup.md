# OBSからAWS IVSへ配信する手順

このアプリの**視聴側(IVS Player)は実装済み**です。実際に映像を流すために足りないのは
「映像をIVSに送り込む(インジェスト)」部分だけで、そこはアプリのコードではなく
AWSコンソールとOBSの設定で完結します。

```
OBS Studio ──RTMPS──▶ IVSチャンネル ──HLS──▶ このアプリのIVSPlayer
   (配信者)              (AWS)                  (視聴者)
```

## 1. IVSチャンネルを用意する

AWSコンソール → **Amazon IVS** → **チャンネル** → 「チャンネルの作成」

| 項目 | 推奨値 | 補足 |
|---|---|---|
| リージョン | `ap-northeast-1` (東京) | 視聴者が国内なら東京。遅延が小さい |
| チャンネルタイプ | `STANDARD` | 複数画質(ABR)に対応。視聴者の回線に応じて自動で画質が切り替わる |
| latency mode | `LOW` | スポーツ中継向け。実測3〜5秒程度 |
| 録画 | 必要なら S3 に設定 | アーカイブ機能をPhase2で実装する際に使う |

`BASIC` タイプは安価ですが単一画質のみで、プレイヤーの画質切替が機能しません。

作成後、チャンネル詳細画面に以下が表示されます。

- **取り込みサーバー (Ingest server)** — `rtmps://xxxxx.global-contribute.live-video.net:443/app/`
- **ストリームキー (Stream key)** — `sk_ap-northeast-1_xxxxxxxx`
- **再生URL (Playback URL)** — `https://xxxxx.playback.live-video.net/.../*.m3u8`

> **ストリームキーは絶対に共有しないでください。** これを知っている人は誰でも
> あなたのチャンネルに映像を流せます。スクリーンショットや issue に貼らないこと。
> 漏れた場合はコンソールから即座にリセットできます。

## 2. OBS Studio を設定する

[OBS Studio](https://obsproject.com/) をインストールし、**設定 → 配信** で以下を入力します。

| 項目 | 値 |
|---|---|
| サービス | カスタム... |
| サーバー | チャンネル詳細の**取り込みサーバー**をそのまま貼り付け |
| ストリームキー | チャンネル詳細の**ストリームキー** |

続いて **設定 → 出力** を「詳細」モードにして、IVSの推奨値に合わせます。

| 項目 | 推奨値 |
|---|---|
| 出力モード | 詳細 |
| エンコーダ | x264(CPU)またはハードウェアエンコーダ |
| レート制御 | CBR |
| ビットレート | 3500〜6000 Kbps(1080p30なら4500前後) |
| キーフレーム間隔 | **2秒**(必須。ここを0や他の値にすると再生が不安定になる) |
| プロファイル | main または high |

**設定 → 映像** で、基本解像度と出力解像度を `1920x1080`、FPSを `30` に。

> IVSの上限は解像度1080p・ビットレート8500Kbps・キーフレーム間隔2秒です。
> 超えると配信が切断されます。

## 3. アプリに再生URLを設定する

チャンネル詳細の**再生URL**を、Vercelの環境変数に設定します。

Vercel → プロジェクト → **Settings → Environment Variables**

| Key | Value |
|---|---|
| `NEXT_PUBLIC_IVS_PLAYBACK_URL` | チャンネルの再生URL(`.m3u8` で終わる文字列) |

Production / Preview / Development の3つにチェックを入れて保存し、
**Deployments から再デプロイ**してください。環境変数はビルド時に埋め込まれるため、
保存しただけでは反映されません。

ローカルで試す場合は `.env.local` に同じ内容を書きます(`.env.example` を参照)。

再生URLは秘密情報ではありません。プレイヤーに埋め込んで配布する前提のものです。
秘密にすべきなのはストリームキーだけです。

## 4. 配信して確認する

1. OBSで「配信開始」
2. アプリの `/live/match-001` を開く

配信が始まるまでの間、プレイヤーは「まだ配信が始まっていません」と表示して
10秒ごとに自動で再読み込みします。OBSで配信を開始すれば、ページを操作しなくても
そのまま再生が始まります。

## 試合ごとに別チャンネルを使う場合

環境変数で指定できるのは1本だけです。複数試合を同時配信するなら、
`lib/api/matches.ts` の各 `Match` の `playbackUrl` にチャンネルごとの再生URLを
設定してください。プレイヤー側(`components/player/IVSPlayer.tsx`)の変更は不要です。

実APIに移行する際は、試合データに `playbackUrl` を持たせてDBから返す形になります。

## 費用について

IVSは**チャンネルを作っただけでは課金されず、配信中の時間と視聴された時間に対して**
課金されます。テストが終わったらOBSの配信を停止してください(チャンネル自体は
残しておいて構いません)。長期間使わないなら、チャンネルを削除しておくと安全です。

最新の料金は [AWS公式の料金ページ](https://aws.amazon.com/jp/ivs/pricing/) を確認してください。

## うまくいかないときの切り分け

**まず再生URLに直接アクセスして、配信が届いているかを確認します。**

```bash
curl -s -o /dev/null -w "%{http_code}\n" "<再生URL>"
```

| 結果 | 意味 | 対処 |
|---|---|---|
| `200` | IVSまで映像が届いている | 問題はアプリ側。ブラウザのコンソールを確認 |
| `404` | チャンネルはあるが配信されていない | OBSが配信中か、ストリームキーが正しいかを確認 |
| その他 | 再生URLが間違っている | チャンネル詳細からURLをコピーし直す |

アプリ側で「まだ配信が始まっていません」と出たままの場合、上記が `404` なら
アプリは正常に動作しています(配信の到着を待っている状態)。
